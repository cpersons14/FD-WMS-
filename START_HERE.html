S3PL Family Dollar WMS

GitHub upload and first Render deployment • November 9, 2026

This copy contains the full pilot application and synthetic tests. It contains no real inventory dataset, orders, credentials or pre-created user accounts. The application starts with an empty database.

1. Make the GitHub repository private

Open your repository → Settings → Danger Zone → Change visibility → Make private. Keep S3PL's application code under company-controlled access.

2. Upload the extracted contents

  1. Right-click S3PL_FD_WMS_Deploy.zip on Windows and choose Extract All.
  2. Open the extracted folder. You should see render.yaml, manage.py, requirements.txt, and the application folders.
  3. Open the GitHub repository's Code tab. For an empty repository, click uploading an existing file. Otherwise use Add file → Upload files.
  4. Select all files and folders inside the extracted folder and drag them onto GitHub. Upload the contents, not the ZIP or its enclosing folder.
  5. Enter Initial FD WMS deployment as the commit message and commit the files to the initial branch.

On the repository's main page, verify that render.yaml, manage.py, requirements.txt, config/ and warehouse/ are visible immediately.

3. Deploy the Blueprint

  1. In Render, select New → Blueprint.
  2. Connect GitHub and select cpersons14/FD-WMS-. Grant Render access to this private repository if prompted.
  3. Use branch main, or the actual branch containing your uploaded files.
  4. Enter Blueprint Path: render.yaml.
  5. Check that the preview contains the Python web service s3pl-fd-wms and PostgreSQL database s3pl-fd-db, both in Ohio.
  6. Review the displayed charges, then click Deploy Blueprint.

The application installs dependencies, runs database migrations and initializes user roles. No inventory is imported. When the service is Live, open its Render-provided URL to reach the login page.

4. Create your administrator

Open the web service's Shell and run:

python manage.py createsuperuser --username colin

Enter your email and choose a password. Password typing is hidden in the Shell. Open /admin/ on the WMS address and sign in. Create individually named accounts and assign S3PL Warehouse or FD Corporate. Keep Staff/Superuser off for ordinary users.

5. Run a controlled trial

Add synthetic test parts and bins through Inventory. Confirm the base unit and pack sizes in Item settings. Test receipt entry, document upload, ordering, picking, packing and shipping before adding actual stock.

Customer email stays disabled. Configure the approved sender, FD Receiving group and email switches using README.md before enabling real delivery. Low-stock email has a separate switch and scheduled command.

Review RECEIVING_WORKFLOW.md, FEATURES.md and VALIDATION.txt. Verify PostgreSQL concurrency, browser behavior, permissions, backups and warehouse acceptance before using the WMS for live dispatch. Load real inventory later into a clean production database through a private transfer, never by committing it to GitHub.
